**Date:** 2026-05-15
**Owner:** Rev Vaughn
**Status:** Draft v1, consensus reached across PM, Marketer, Architect, Engineer, and Founder/User roles

## 1. Executive Summary

A mobile-first, founder-branded membership platform for delivering paid digital programs (video, audio, PDF, Q&A recordings, written guides) to a small, high-value client base. The product is built around three non-negotiables:

1. **Mobile-first.** The phone is the product. Every design decision is made phone-first, desktop second.
2. **Premium feel.** Reflects a high-ticket personal brand — never generic SaaS.
3. **Effortless for the founder.** Publishing a new lesson takes under 60 seconds. Setup takes under one afternoon.

**Scale at launch:** Under 100 members, 1–3 programs. Built to comfortably reach several hundred members without re-architecture.

**Build approach:** Custom (Next.js on Vercel + Clerk + Neon + Stripe + Mux). Buy auth, video, billing, and email. Build the content model, access control, and admin experience.

**Timeline:** 6-week target, 8-week hard ceiling.

## 2. Goals & Non-Goals

### Goals
- Deliver paid digital programs to members with bulletproof access control
- Look and feel premium on iPhone first, desktop second
- Let the founder publish new content from a phone in a coffee shop with no tutorial
- Support all four monetization models: one-time purchase, subscription, tiered access, freemium
- Convert browsers to buyers from inside the product (in-product upgrade CTAs)
- Reach beta launch with 5–10 real members within 6 weeks

### Non-Goals (V1)
- Community feed, threaded discussions, member-to-member messaging
- Calendar, event scheduling, live Q&A booking (Q&A *recordings* are content, not events)
- Native iOS/Android apps (PWA covers v1)
- Gamification, badges, streaks, leaderboards
- Affiliate / referral program
- Built-in email marketing automation (transactional emails only; webhook to external tools)
- Certificates of completion
- Multi-tenant white-label for clients (Rev is the only tenant in v1)
- Custom landing page builder (sales pages live outside the membership)

## 4. Core User Flows

### Flow 1 — New Member Purchase & First Session
1. External sales page → Stripe Checkout
2. Auto-account creation via Clerk (magic link or Google)
3. Welcome email fires (Resend) + webhook fires to external email tool (Zapier/Make → MailerLite)
4. Redirect to **Start Here** page for purchased program
5. Member sees Rev's photo, 2-minute welcome video, and one CTA: "Start Module 1"
6. First lesson loads and is immediately playable
**Target: Stripe payment → first lesson playing in under 3 minutes**

### Flow 2 — Returning Member Content Access
1. Open phone → tap installed PWA icon (or visit URL)
2. Magic link or Google sign-in → one tap
3. Dashboard shows: "Continue where you left off" (last lesson + resume timestamp)
4. Tap → lesson plays from exact second they paused
5. Mark complete → next lesson queued
**This is 80% of all sessions. Must be fast and decision-free.**

### Flow 3 — Member Upgrades from Free or Lower Tier
1. Logged-in free/basic member taps a locked lesson
2. In-product gate shows: lesson preview (60s) + price + "Upgrade for $X" CTA
3. Tap → Stripe Checkout (already authenticated, pre-filled)
4. Webhook fires → Entitlement updated → access unlocks immediately
5. Return to same lesson, now unlocked
**No re-login, no page reload, no "check your email."**

### Flow 4 — Founder Publishes New Content
1. Open admin (mobile or desktop) → tap "+ New Lesson"
2. Choose program → choose module (or skip if program has only one)
3. Pick type: Video (paste Vimeo/Loom URL or upload to Mux), PDF (drag-drop), Audio (drag-drop), Markdown (paste)
4. Type title → set required tier → publish
**Target: under 60 seconds, 4 clicks, works on phone**

### Flow 5 — Founder Manages Members
1. Admin → Members list (searchable, sortable)
2. Tap a member → see their access, purchase history, progress
3. One-tap actions: refund, grant access manually, revoke access, send password reset
4. Bulk: paste CSV of emails → assign program → invite (magic links sent)

## 5. Feature Specification — V1

### 5.1 Authentication
- Clerk-hosted sign-in/sign-up
- Magic link (primary) and Google sign-in (secondary)
- Password optional (Clerk default)
- Custom-branded sign-in screen with Rev's logo and primary color
- One subdomain: `members.[revsdomain].com`

### 5.2 Content Model & Hierarchy
- **Program** → **Module** (optional) → **Lesson**
- If a program has only one module, the UI flattens to Program → Lessons (Module hidden)
- Lessons have a `type` field: `video_mux`, `video_embed`, `audio`, `pdf`, `markdown`
- Lessons can be marked `is_preview: true` to be visible to free/lower tiers
- Drag-and-drop reordering for modules and lessons (mobile-friendly long-press + drag)

### 5.3 Content Viewer (Member-Facing)
- **Video:** Mux player for owned video (adaptive bitrate, signed playback URLs), iframe embed for Vimeo/Loom external content. Resume playback per user (last position stored server-side). Picture-in-picture supported on iOS.
- **Audio:** HTML5 audio + custom shadcn controls. Lock-screen playback (Media Session API) so it works like a podcast.
- **PDF:** In-browser viewer (react-pdf) with one-tap download. PDFs watermarked with buyer email at request time (pdf-lib) for high-value programs.
- **Markdown:** Server-rendered with react-markdown + shiki (for any code), large typography, mobile-optimized line length.
- **External embed:** Bare iframe with secure sandboxing.

### 5.4 Progress Tracking
- Lesson `completed_at` per user
- Video `last_position_seconds` per user
- Module % complete shown in program view
- Program % complete shown on dashboard
- "Continue where you left off" pinned to dashboard top

### 5.5 Access Control (Entitlement Model)
Three-layer enforcement, server-side:
1. **Session layer:** Clerk middleware on all `/app/*` routes
2. **Entitlement layer:** Single function `canAccessLesson(userId, lessonId)` called from every server component / route handler. Reads `entitlements` table.
3. **Asset layer:** All Mux/Blob assets served via signed URLs minted server-side after entitlement check. Direct URLs never exposed.

Stripe webhooks are the only automated writer of entitlements. Manual admin grant is the only other write path.

### 5.6 Monetization (All Four Models)
**Data model supports all from day one. UI exposes:**
- **Free tier:** Account creation with no payment; access to lessons marked `is_preview` across designated free programs
- **One-time purchase:** Lifetime access to a single program
- **Subscription (monthly or annual):** Recurring access; cancellation drops member back to free tier at period end (they stay in the system for re-engagement, do not lose account)
- **Tiered access:** Subscriptions can be `basic` or `pro` tier; pro unlocks more programs / preview-only content

All pricing configured in Stripe; product UI reads Stripe price IDs. No custom billing logic.

### 5.7 Checkout & Billing
- Stripe Checkout (hosted) for all purchases
- Stripe Customer Portal for self-serve cancel/upgrade/payment method updates
- Webhook handler at `/api/webhooks/stripe` updates `entitlements` table idempotently
- Receipt emails via Stripe (default) + custom welcome email via Resend

### 5.8 In-Product Upgrade CTAs
Every locked lesson shows:
- Lesson title and description (visible)
- Preview snippet (60s of video, first paragraph of MD, or first PDF page)
- Price + benefit copy: "Unlock the full [Module Name] — $X"
- One-tap CTA → Stripe Checkout

### 5.9 Start Here Page (Per Program)
Configurable by founder per program:
- Headline + subheadline
- Welcome video embed
- One primary CTA (defaults to "Start Module 1")
- Optional "first action" text (e.g., "Before you watch lesson 1, do this:")

### 5.10 Founder Branding
- Custom logo (uploaded)
- Custom primary color
- Custom header photo (Rev's face on every member-facing page header)
- Custom domain via Vercel
- **Zero "Powered by" branding anywhere members can see**

### 5.11 Search (Basic)
- Postgres LIKE query across lesson titles and descriptions, scoped to user's entitled content
- One search bar in dashboard nav
- Full-text search (Postgres tsvector or Algolia) deferred to v1.1

### 5.12 Admin Experience
Mobile-responsive admin at `/admin`, gated to founder's user ID.

**Programs:**
- List view → tap to edit
- Create new program: title, slug, description, header image, pricing tier rules
- Duplicate program (one-click clone for v2 launches)
- Archive program (hides from members, preserves data)

**Modules & Lessons:**
- Drag-and-drop reorder (works on mobile via long-press)
- Quick-add lesson: type → paste URL or drag file → title → publish

**Members:**
- Searchable list
- Detail view: access, purchases, progress, last login
- One-tap actions: refund (via Stripe API), grant access, revoke access, send magic link
- CSV bulk import → assign to program → send invites

**Settings:**
- Brand (logo, color, header photo, domain)
- Stripe connection
- Email integration webhook URL
- Founder profile (name, bio, photo)

### 5.13 Transactional Email
Via Resend with React Email templates:
- Account welcome (on first sign-up)
- Purchase confirmation (on successful Stripe charge)
- Magic link / password reset (handled by Clerk, branded with Rev's logo)
- Access revoked (on subscription cancellation, sent at period end)

### 5.14 Webhook to External Email Tool
Single configurable webhook URL fired on key events:
- `member.signup`
- `member.purchase`
- `member.subscription_canceled`
- `member.lesson_completed` (optional)

Payload includes member email, program slug, tier, and event metadata. Rev pipes this to MailerLite/Zapier/Make for nurture sequences.

### 5.15 PWA
- Installable manifest with Rev's branding
- Service worker caches app shell for offline
- Downloadable PDFs cached locally for offline reading
- "Add to Home Screen" prompt after second session

## 7. Technical Architecture

### 7.1 Stack
| Layer | Choice | Rationale |
|---|---|---|
| Framework | Next.js 16 (App Router) | Largest LLM training corpus; native Vercel skills; server components fit access model |
| Language | TypeScript (strict) | Catches errors before runtime; critical for non-dev builder |
| Hosting | Vercel | One-command deploy, preview URLs, edge middleware |
| Auth | Clerk | Drop-in Next.js middleware, magic links, branded UI |
| Database | Neon Postgres (via Vercel) | Serverless, branch-per-preview, scales to zero |
| ORM | Drizzle | Type-safe SQL, lighter than Prisma, clean Claude output |
| Payments | Stripe (Checkout + Customer Portal + Billing) | Industry standard, hosted UI removes whole categories of bugs |
| Video | Mux | Signed playback, adaptive bitrate, mobile-optimized HLS |
| Asset storage | Vercel Blob | Native to Vercel, signed URLs, no S3 IAM overhead |
| Email | Resend | React Email templates, trivial Next.js DX |
| UI | shadcn/ui + Tailwind v4 | Copy-into-repo components (Claude can read/modify); mobile-first utility classes |
| PWA | Next.js manifest + service worker | No native app overhead |

### 7.2 Core Data Model
```
User (Clerk-owned identity; we mirror clerk_user_id + profile fields)
  └─ has many Entitlements
  └─ has many Progress records
  └─ has many Purchases

Program
  ├─ has many Modules (ordered, optional)
  └─ mapped to many Products

Module
  └─ has many Lessons (ordered)

Lesson
  ├─ type: video_mux | video_embed | audio | pdf | markdown
  ├─ asset_ref: Mux playback_id | Blob URL | external URL | inline MD text
  ├─ required_tier: free | basic | pro
  └─ is_preview: bool

Product (Stripe-mapped SKU)
  ├─ stripe_price_id
  ├─ pricing_model: one_time | subscription
  ├─ tier: free | basic | pro
  └─ grants_access_to: Program(s) — many-to-many

Entitlement (SINGLE source of truth for access)
  ├─ user_id
  ├─ program_id
  ├─ tier
  ├─ source: stripe_subscription | stripe_payment | manual_grant
  ├─ status: active | past_due | canceled | expired
  └─ expires_at (nullable)

Progress
  ├─ user_id, lesson_id
  ├─ completed_at
  └─ last_position_seconds

Purchase (immutable audit log of Stripe events)
```

### 7.3 Access Control Implementation
- `canAccessLesson(userId, lessonId)` lives in `/lib/entitlements/` — single function, called everywhere
- Returns boolean + reason (`no_entitlement | wrong_tier | expired | ok`)
- Server-side only; client UI receives boolean, never the logic
- Tested manually via end-to-end Playwright script before every deploy

### 7.4 Repository Structure
```
/app
  /(marketing)         ← public sales pages
  /(app)               ← authenticated member experience
    /dashboard
    /programs/[slug]
    /lessons/[id]
    /account
  /(admin)             ← founder-only
    /programs
    /members
    /settings
  /api
    /webhooks/stripe
    /asset/[lessonId]  ← signed-URL gateway
/components
  /ui                  ← shadcn primitives
  /lesson              ← VideoPlayer, PdfViewer, AudioPlayer, MarkdownLesson
  /layout              ← MobileNav, AppShell
/lib
  /db                  ← Drizzle schema + client
  /auth                ← Clerk helpers
  /entitlements        ← canAccessLesson, grantEntitlement
  /stripe              ← Stripe client + webhook handlers
/emails                ← React Email templates
```

### 7.5 Testing Strategy
- **TypeScript strict** + **Zod schemas** at every form/webhook boundary → catches 60% of bugs at write time
- **One Playwright smoke test** in CI: sign up → buy → view lesson → sign out. If this passes, the critical path works.
- **Manual checklist** (markdown file in repo) Rev runs before every production push
- **Sentry** for error tracking (free tier)
- **Vercel Analytics** for page-level visibility

## 8. Mobile-First Design Principles

1. **Phone-first layout.** Every page designed at 390px width first, scaled up.
2. **Thumb zones.** Primary CTAs in bottom third of screen. Bottom tab nav for app shell.
3. **Tap targets ≥44px.** Apple HIG minimum.
4. **Edge-to-edge video.** No letterboxing on phone. Native fullscreen on tap.
5. **Lock-screen audio.** Media Session API so audio lessons play like podcasts.
6. **Instant feel.** Page transitions under 200ms. Skeleton states for any wait over 100ms.
7. **No hover states for primary actions.** Touch-first interaction.
8. **Single-column everything on mobile.** No cramped two-column layouts.
9. **Big type.** 18px body minimum on mobile, generous line-height.
10. **Black/white minimal default theme.** Brand accents sparingly. Premium, not loud.

## 11. Open Questions & Risks

### Open Questions
1. **Custom domain timing.** Set up `members.revvaughn.com` in Week 1 or Week 6? Recommendation: Week 1, so Rev can share preview links from the real domain.
2. **Mux vs. Bunny Stream for video.** Mux for v1 (better DX). Revisit if monthly video bill exceeds $200.
3. **Watermarking PDFs by default.** Apply to all PDFs, or only programs priced over $X? Recommendation: all PDFs in paid programs, none in free.
4. **Admin user model.** V1 has one admin (Rev). Add second admin / VA seat support in v1.1?

### Risks
1. **Solo builder gets stuck on a non-trivial bug.** Mitigation: budget $300–$500/week of a senior Next.js dev's on-call time as insurance.
2. **iOS Safari PWA quirks** (notifications, install prompt). Mitigation: test on real iPhone weekly, don't depend on push notifications in v1.
3. **Stripe webhook reliability.** Mitigation: idempotency keys on every entitlement write, webhook retry handling, dead-letter logging.
4. **Founder over-scopes mid-build.** Mitigation: any new request after Week 2 goes to v1.1 list automatically. No exceptions.
